# Web Shop setup

Completion now has one Complete action, which navigates directly to Orders, the first Shop tab. Customer-shop, catalog, balance-book and review-again actions were removed from this completion page. Completing clears the current wizard-access flag; server progress still must be saved before success is shown.

Address-bar IDs now match the five visible tabs: Shop details=1, Payments=2, Products=3, Sales AI=4, Review=5. API progress still uses its stable version-2 stage IDs internally. URL updates preserve the current history entry and retained state; reload/older saved progress is translated before displaying the tab.

Shop details layout: two columns, with a compact 16:9 cover and overlapping shop logo in the left column and public name, slug, phone and three-line address stacked in the right column. Setup-only camera edit controls reuse the existing upload APIs and preserve loading, errors and saved-image previews. Successful cover upload is announced to assistive technology without shifting the overlapping avatar. Other Shop branding screens keep their existing layout. Browser checks assert column alignment, avatar overlap before/after uploads and no overflow at 1024/1280/1440 widths, including Myanmar and dark mode.

Scope: PwarMyar web app. Shop setup opens automatically for the business owner after location approval when the shop has no meaningful configuration, regardless of how many times the owner visited before. There are no setup navigation or header links. Generated storefront defaults, the standard cash option, inherited business contact fields and approved GPS coordinates do not count as shop configuration. Custom storefront/fulfillment/payment settings, published products, shop contacts, saved Sales AI settings, a shop cover or existing orders count as configured data. Pending setup resumes its saved step. A completion marker alone does not suppress setup if the shop is still empty. Owners who already configured the shop do not get a new wizard; staff and expired subscriptions do not enter it.

The five steps are Shop details, Payments, Products, Sales AI and Review. URL parameter `shopSetupStep` uses visible numbers 1 through 5. Persisted API progress retains shared server IDs 1, 4, 5, 6 and 7 internally; saved legacy API stages 2 and 3 resume at Payments. The existing authenticated session and Laravel APIs are reused; the location response now includes business-scoped setup progress and PUT /shop-admin/setup persists owner-only progress behind the existing location, subscription and settings permission checks. The existing settings table stores the marker; no schema migration is required.

| Step | Capabilities and persistence |
| --- | --- |
| Shop details | Existing logo/cover uploads, public name, locked-after-orders slug, phone and three-line address. Currency, online price selector and shop description are hidden. Saving defaults to Retail and preserves the existing currency/description. |
| Payments | Bank/wallet, account holder, account number/phone and checkout availability; add/remove new methods. Method name, method type selector and customer instructions are hidden. New names derive from bank/wallet (fallback Bank transfer); existing names, instructions and hidden cash are preserved. |
| Products | Existing bounded, paginated publication table and row controls, debounced search, stock, sales unit and current online price. Publication saves immediately with the existing price/stock validation. The Products workspace is available for product creation and pricing when that module is enabled. |
| Sales AI | Enable switch and representative name only. Advanced settings and optimistic-concurrency version are preserved. Conflicts can reload AI settings, and wallet credit notices remain available. |
| Review | Saved shop/payment/AI summary and explicit storefront/order/marketplace controls, initially checked. No delivery or product-readiness summary. Completion links to customer shop, publication and AI balance book. |

Each settings save merges only the fields owned by the current step into the last server response and sends the existing settings whitelist. Visiting another step cannot publish unsaved review choices. Method IDs are assigned once in the draft, so validation retries do not create duplicates. The settings endpoint saves nested configuration atomically. AI uses its own existing version check. Busy refs guard repeated submit events. Leaving during a request does not let its completion pull the user back into setup.

The workspace and wizard are separate retained frames. Source query, filters, table/page and scroll remain mounted. The wizard retains drafts and the visited product table across step navigation. Close/page Back/app-bar Back leave onboarding for Storefront (or the captured history entry when present); browser Back and Forward follow the same step history. Direct links have a Storefront fallback. Settings/publication changes reconcile affected Shop views; an unchanged return never triggers an initial source load. Returning to Orders after a setup change does not reload unrelated order data. Account/tenant identity uses the existing application remount boundary.

Design: compact desktop shell, bounded two-column wizard, shared theme tokens, shared locale switch, subtle static background decoration, natural page scrolling, visible keyboard focus and reduced-motion support. English/Myanmar additions are frontend-local. Existing logo and cover components retain their established file validation and edit actions. Completion is shown only after the progress marker is saved successfully; a failed progress save can be retried. This final UI sync updates both PwarMyar web and mobile while preserving project-specific branding and deployment configuration.
