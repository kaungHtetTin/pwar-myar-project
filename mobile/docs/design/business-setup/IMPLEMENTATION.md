# PwarMyar mobile business setup

Parity inventory: first-time owner/pending-progress gate; saved-stage deep links; business name, optional phone/address, currency and time zone; protected currency; optional logo upload/replacement/removal and file errors; Cash plus wallet/bank/custom payment choices; first product with purchase-unit conversion, opening stock, cost and retail price; permissions; field errors; busy/duplicate-submit guards; completion retry without duplicate product; completion destinations; language switching; forward/backward motion and reduced motion; Finish later and a reminder; preserved source/draft state and shared refresh.

Dedicated form routes: `/setup/business`, `/setup/payments`, `/setup/product`; completion: `/setup/complete`. Registration enters Business basics directly. An owner with pending setup resumes the saved stage on an online login. Existing/completed businesses, staff and offline mode do not start onboarding. There is no setup drawer item. Server state is shared with desktop using the existing business-setup and settings-logo endpoints.

The page is inside AppShell and its SwipeRefreshShell, uses PageAppBar and the shared controls/locale switch/logo frame, and registers a setup refresh that preserves edited fields. Workspace views remain in RetainedViews while the setup component keeps its drafts above step changes. App-bar/page/browser Back use the existing root navigation. Finish later returns to the captured source entry; a deep link falls back to the enabled workspace root. Drafts are scoped by the authenticated component key and disappear on logout or tenant change. Form mutations announce only their affected resources. A product saved before a completion error is retained by its server product ID.

Intentional mobile design differences: the desktop sidebar/marketing introduction is replaced by a compact three-step progress row. Fields and actions have touch targets of at least 44 px, and the cards scroll naturally instead of shrinking to fit a screen. The standard bottom workspace navigation and trial banner are hidden while onboarding is active. Primary actions remain after the form content so they do not obscure focused fields or the keyboard. Static payment choices and the finite server-provided time-zone configuration use ordinary choices/select controls; there are no dynamic entity lists requiring endless scrolling in this flow.

Validation and visual evidence are recorded in `artifacts/mobile-business-setup/` at repository root. The browser script intercepts API requests, so fixtures never modify real accounts. There is no native Android-specific wizard code; device Back uses the existing shared navigation integration. Reference screenshots from the desktop setup conversation guide content and hierarchy rather than desktop geometry.

Setup background: the shared app bar uses transparent surface/border tokens with no elevation. A viewport-fixed, non-interactive layer continues behind the header and content, using theme-colored glows and fine concentric arcs. Cards retain opaque shared surfaces for form contrast in light and dark themes; the decoration adds no movement or horizontal overflow.
